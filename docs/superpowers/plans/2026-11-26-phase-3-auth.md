# MailMCP: 3. fázis (OAuth, CIMD, mindig bekapcsolt hitelesítés) implementációs terv

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A szerver saját OAuth authorization szervert kap (CIMD, PKCE, erőforráshoz kötött, cserélődő tokenek, jelszó és TOTP bejelentkezés, próbálkozáskorlát), és minden `/mcp` kérés érvényes Bearer tokent kér, lokálisan is. A futtatókörnyezet Node 26 LTS.

**Architecture:** Az `src/auth/` modulok tisztán, injektált órával és tárolóval működnek: jelszó és TOTP (`password.ts`, `totp.ts`), tokenek (`tokens.ts`), próbálkozáskorlát (`limiter.ts`), CIMD (`cimd.ts`), authorize folyamat (`flow.ts`) és a bejelentkező oldal (`login-page.ts`). A tartós adat a `src/store/store.ts` SQLite tárolójában van (`node:sqlite`). A HTTP réteg (`src/http/oauth-routes.ts`, `src/http/app.ts`) a Hono útvonalakat köti be, a `/mcp` végpontok elé az SDK `requireBearerAuth` kapuja kerül. A `src/cli.ts` a titkokat állítja elő és az engedélyezéseket kezeli.

**Tech Stack:** a 2. fázisé, Node 26.13.1-en. Új futásidejű függőség nincs: `node:sqlite`, `node:crypto` (`argon2Sync`, HMAC, SHA-256). Dev: `@types/node` 26.

**Spec:** [`docs/superpowers/specs/2026-11-22-mailmcp-design.md`](../specs/2026-11-22-mailmcp-design.md), különösen az „OAuth és biztonság” fejezet és a „Hitelesítés (3. fázis döntései)” tábla (D26-D37), a „Beállítások” tábla és a „Mért tények”.

## Global Constraints

- **A tokenek és code-ok `crypto.randomBytes`-ból készülnek**, soha `Math.random`-ból. Tokenhez és jelszóhoz összehasonlítás csak `crypto.timingSafeEqual`-lal (azonos hosszú pufferen).

- **Az erőforrás-azonosító a konfigból jön** (`MAILMCP_PUBLIC_URL`), soha a kérés URL-jéből: a Traefik mögött a kérés sémája `http`, a nyilvános cím `https`.
- **Hibás `client_id` vagy `redirect_uri` esetén soha nincs átirányítás** (D31).
- **Értékek a specből, pontosan:** access token 3600 s, refresh token 30 nap, code 60 s, függő kérés 10 perc, CIMD gyorsítótár 10 perc, CIMD letöltés 5 s és 64 KiB, korlát 5 hiba / 15 perc / 15 perc tiltás, globális 20 hiba / 15 perc után 3 másodpercenként egy kísérlet, argon2id `m=19456,t=2,p=1`, só 16 bájt, kimenet 32 bájt, TOTP 30 s, 6 számjegy, ±1 lépés.

## Könyvtár tények (mérve 2026-11-26)

- **Node 26.13.1:** `import { DatabaseSync } from 'node:sqlite'` (a `@types/node` 26.6.11 csak ezt a nevet ismeri; futásidőben a `Database` aliasa). `db.exec(sql)`, `db.prepare(sql).run(...params) → { changes, lastInsertRowid }`, `.get(...) → row | undefined`, `.all(...)`. Betöltéskor nincs „experimental” figyelmeztetés. `crypto.argon2Sync('argon2id', { message, nonce, parallelism, tagLength, memory, passes }) → Buffer`. Ellenőrző vektor: `argon2Sync('argon2id', { message: 'password', nonce: 'somesalt', passes: 2, memory: 65536, parallelism: 4, tagLength: 24 })` base64 alakja `F1jG2CV3/Nr+yRuIsPKw0J9r4s7cJHBU`; ugyanez `argon2i`-vel `RdescudvJCsgt3ub+b+dWRWJTmaaJObG`, ami az argon2 referencia implementáció README vektora.
- **MCP SDK 2.4.0** (`@modelcontextprotocol/server`): `requireBearerAuth({ verifier, expectedResource?: URL, resourceMetadataUrl?: string }) → (req: Request) => Promise<AuthInfo | Response>`. A `verifier.verifyAccessToken(token) → Promise<AuthInfo>` hibánál `new OAuthError(OAuthErrorCode.InvalidToken, message)`-t dob; az `AuthInfo` `{ token, clientId, scopes, expiresAt (másodperc), resource: URL }`, lejárat nélkül a kapu elutasít. `getOAuthProtectedResourceMetadataUrl(new URL('http://127.0.0.1:8787/mcp/work'))` → `http://127.0.0.1:8787/.well-known/oauth-protected-resource/mcp/work`. `buildOAuthProtectedResourceMetadata({ oauthMetadata, resourceServerUrl, scopesSupported, resourceName })` `127.0.0.1` http issuerrel is működik, és `{ resource: 'http://127.0.0.1:8787/mcp/work', authorization_servers: ['http://127.0.0.1:8787'], scopes_supported, resource_name }`-t ad. `hostHeaderValidationResponse(req, [hostname])`, `originValidationResponse(req, [hostname])` (mindkettő hostnév alapú, port nélkül). `createMcpHandler(...).fetch(request, { authInfo })`.
- **Hono 4.13.19, @hono/node-server 2.1.11:** `import { getConnInfo } from '@hono/node-server/conninfo'` → `getConnInfo(c).remote.address`; csak valódi Node szerveren működik, ezért a tesztek a címet injektálják. `c.req.parseBody()` form törzsre `Record<string, string | File>`.
- **Claude Code CIMD** (2026-11-26): `{"client_id":"https://claude.ai/oauth/claude-code-client-metadata","client_name":"Claude Code","client_uri":"https://claude.ai","redirect_uris":["http://localhost/callback","http://127.0.0.1/callback"],"grant_types":["authorization_code","refresh_token"],"response_types":["code"],"token_endpoint_auth_method":"none"}`. A tesztek ezt a dokumentumot adják vissza az injektált `fetch`-ből.
- **RFC 6238 tesztvektorok** (SHA1, kulcs ASCII `12345678901234567890`, 8 számjegy): T=59 → `94287082`, T=1111111109 → `07081804`, T=1111111111 → `14050471`, T=1234567890 → `89005924`, T=2000000000 → `69279037`, T=20000000000 → `65353130`. 6 számjegynél ezek utolsó hat jegye.
